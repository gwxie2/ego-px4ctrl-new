# 常见问题排查

本文档汇总系统使用中的常见问题及解决方案。

## 启动问题

### 问题 1：catkin_make 失败

**症状**：
```
Could not find package 'px4'
```

**原因**：未 source 环境脚本

**解决方案**：
```bash
source tools/source_phase1_env.sh
catkin_make -j4
```

### 问题 2：TakeoffLand 消息未定义

**症状**：
```
quadrotor_msgs/TakeoffLand: message type not found
```

**原因**：使用了外部 quadrotor_msgs

**解决方案**：
```bash
# 确认使用本地版本
ls src/quadrotor_msgs/msg/TakeoffLand.msg

# 清理重构建
rm -rf build devel
catkin_make -j4
```

### 问题 3：MAVROS 连接失败

**症状**：
```
/mavros/state: connected: false
```

**原因**：
1. PX4 SITL 未启动
2. 启动顺序错误（多机场景）
3. 端口冲突

**解决方案**：
```bash
# 单机：等待 PX4 启动
roslaunch clean_uav_core phase1_px4_sim.launch

# 多机：先启动仿真层，等待 10-15 秒
roslaunch clean_uav_core phase2_px4_multi_sim.launch
# 等待...
roslaunch clean_uav_core phase2_dual_uav_stack.launch
```

## 运行问题

### 问题 4：无人机不起飞

**症状**：无人机停留在地面，电机不转

**检查清单**：

```bash
# 1. MAVROS 连接
rostopic echo /mavros/state -n 1
# 期望：connected: true, armed: true/false

# 2. 里程计
rostopic echo /truth_odom -n 1
# 期望：有输出

# 3. 起飞指令
rostopic echo /px4ctrl/takeoff_land
# 期望：takeoff_land_cmd: 1

# 4. 控制器状态
rostopic echo /px4ctrl/debug | grep state
# 期望：AUTO_TAKEOFF
```

**常见原因**：
- `use_takeoff_trigger:=false` → 设置为 `true`
- `takeoff_delay` 太短 → 增加到 8.0 秒
- `no_RC` 未启用 → 检查配置文件

### 问题 5：起飞后不移动

**症状**：无人机悬停，不飞向目标

**检查清单**：

```bash
# 1. 规划触发器
rostopic echo /traj_start_trigger

# 2. 规划器输出
rostopic echo /planning/bspline

# 3. 位置指令
rostopic echo /position_cmd
```

**常见原因**：
- 规划触发器未发布 → 增加 `traj_trigger_delay`
- 目标点未设置 → 检查 `target_x/y/z`
- 规划器在 WAIT_TARGET → 检查目标点话题

### 问题 6：飞行不稳定/震荡

**症状**：无人机左右摇摆，难以稳定

**可能原因**：

1. **PID 增益过高**
   ```yaml
   # 降低增益
   gain:
     Kp0: 1.0   # 从 1.5 降低
     Kv0: 1.2   # 从 1.5 降低
   ```

2. **速度设置过高**
   ```bash
   # 降低速度
   planner_max_vel:=1.5
   planner_max_acc:=2.0
   ```

3. **仿真负载过高**
   ```bash
   # 关闭 GUI
   gui:=false
   ```

### 问题 7：IMU 频率告警

**症状**：
```
[px4ctrl] IMU frequency too low: 15 Hz (threshold: 30 Hz)
```

**原因**：仿真负载过高

**解决方案**：
```bash
# 1. 关闭 GUI
gui:=false

# 2. 降低模型复杂度
# 移除 heavy 模型，使用 simple 模型

# 3. 调整告警阈值（临时）
msg_timeout:
  imu: 1.0  # 从 0.5 增加到 1.0
```

## 多机问题

### 问题 8：多机连接失败

**症状**：第二架无人机无法连接

**原因**：启动顺序错误

**解决方案**：
```bash
# 必须按以下顺序
# 终端 1：先启动仿真层
roslaunch clean_uav_core phase2_px4_multi_sim.launch

# 等待 10-15 秒...

# 终端 2：再启动算法层
roslaunch clean_uav_core phase2_dual_uav_stack.launch
```

### 问题 9：话题命名空间混乱

**症状**：UAV0 和 UAV1 数据交叉

**检查**：
```bash
# 检查话题命名空间
rostopic list | grep uav0
rostopic list | grep uav1

# 检查话题映射
rostopic info /uav0/position_cmd
rostopic info /uav1/position_cmd
```

**解决方案**：确保 launch 文件中的 remap 正确

### 问题 10：双机碰撞风险

**解决方案**：
```bash
# 1. 启用轨迹广播
use_traj_broadcast:=true

# 2. 启用避碰
use_collision_avoidance:=true

# 3. 设置安全裕度
planner_safe_margin:=0.5
```

## 性能问题

### 问题 11：仿真太慢

**症状**：Gazebo 运行缓慢，实时率 < 0.5

**解决方案**：
```bash
# 1. 关闭 GUI
gui:=false

# 2. 降低物理精度
# 编辑 world 文件，设置 <max_step_size>0.002</max_step_size>

# 3. 减少模型复杂度
# 移除不必要的传感器

# 4. 使用 headless 模式
roslaunch clean_uav_core phase1_fullstack.launch gui:=false
```

### 问题 12：CPU 占用过高

**症状**：CPU 占用 > 80%

**解决方案**：
```bash
# 1. 减少无人机数量
drone_num: 2  # 从 3 减少到 2

# 2. 降低规划频率
# 编辑 launch 文件，设置规划频率
<param name="planning/trajectory_publish_rate" value="10"/>

# 3. 关闭可视化
enable_visualization:=false
```

## VINS 问题

### 问题 13：VINS 初始化失败

**症状**：VINS 估计器不稳定，频繁重置

**检查**：
```bash
# 1. 检查 VINS 健康度
rostopic hz /iris_0/vins_estimator/odometry
# 期望：> 10 Hz

# 2. 检查图像输入
rostopic hz /iris_0/camera/image_raw
# 期望：30 Hz
```

**解决方案**：
```bash
# 1. 使用回退模式
odom_mode:=vins_with_fallback

# 2. 增加初始化时间
vins_init_time:=10.0
```

### 问题 14：轨迹跟踪误差大

**症状**：使用 VINS 后跟踪误差明显增大

**原因**：VINS 漂移或延迟

**解决方案**：
```bash
# 1. 检查 VINS 质量
rostopic echo /iris_0/vins_estimator/odometry -n 1

# 2. 调整控制增益补偿
# 增加 Kv 增益
gain:
  Kv0: 2.0   # 从 1.5 增加
```

## 应急措施

### 紧急停止

```bash
# 方法 1：发送 LAND 指令
rostopic pub /px4ctrl/takeoff_land quadrotor_msgs/TakeoffLand \
  "header: {stamp: now}" "takeoff_land_cmd: 2" -1

# 方法 2：直接 Ctrl+C 终止 launch
# 注意：这会导致无人机坠落（仿真中可接受）
```

### 重置仿真

```bash
# 停止所有节点
# Ctrl+C 所有终端

# 清理 ROS
rosnode kill -a
rm -rf ~/.ros/log/*

# 重新启动
roslaunch clean_uav_core phase1_fullstack.launch
```
