# 基准测试框架

## 概述

本系统包含完整的性能评估框架，用于量化系统在不同压力条件下的表现。

## 测试阶段

```
基准测试体系
├── Phase A：速度梯度测试
├── Phase B：感知恢复与安全裕度
├── Phase C：时间-平滑权衡
├── Stage D：极限速度探索（10m/s）
├── Stage E：感知退化压力测试
└── Stage F：实际场景验证
```

## 评估指标

### 核心指标

| 指标 | 说明 | 单位 |
|------|------|------|
| **成功率** | 任务完成率 | % |
| **飞行时间** | 总飞行时长 | s |
| **跟踪误差** | 位置跟踪精度 | m |
| **控制滞后** | 指令响应延迟 | ms |
| **规划延迟** | 规划器耗时 | ms |
| **安全间距** | 最小障碍物距离 | m |
| **违规次数** | 安全阈值违反次数 | - |
| **Jerk 积分** | 运动平滑度 | - |
| **重规划成功率** | 重规划成功率 | % |

### 次要指标

| 指标 | 说明 | 单位 |
|------|------|------|
| **规划频率** | 规划器更新频率 | Hz |
| **控制频率** | 控制器输出频率 | Hz |
| **IMU 频率** | 传感器采样频率 | Hz |
| **CPU 占用** | 计算资源使用 | % |
| **内存占用** | 内存使用量 | MB |

## 测试场景

### Phase A：速度梯度

**目的**：评估不同速度下的系统表现

**配置**：
```yaml
speed_profiles:
  - name: slow
    max_vel: 1.0
    max_acc: 2.0

  - name: nominal
    max_vel: 2.0
    max_acc: 3.0

  - name: fast
    max_vel: 5.0
    max_acc: 4.0
```

**结论**：
- 5m/s 可完成任务，但控制滞后显著
- 中速场景（2-3m/s）是性能与安全的平衡点

### Phase B：感知恢复

**目的**：评估感知频率/覆盖对系统的影响

**配置**：
```yaml
perception_modes:
  - name: baseline
    depth_rate: 30
    fov: 90

  - name: perception_clearance_plus
    depth_rate: 30
    fov: 120
    clearance: 0.3
```

**结论**：
- perception_clearance_plus 是最优方案
- 提升感知覆盖比单纯加快重规划更有效

### Phase C：时间-平滑权衡

**目的**：评估不同优化目标的权衡

**配置**：
```yaml
optimization_modes:
  - name: time_priority
    weight_time: 10.0
    weight_smooth: 1.0

  - name: smooth_priority
    weight_time: 1.0
    weight_smooth: 10.0

  - name: balanced
    weight_time: 5.0
    weight_smooth: 5.0
```

**结论**：
- time_priority 不可作为默认策略
- smooth_priority 提供更好的跟踪性能

### Stage D：极限速度

**目的**：探索 10m/s 速度边界

**配置**：
```yaml
extreme_speed:
  max_vel: 10.0
  max_acc: 8.0

rigid_settings:
  clearance: 0.3
  lambda_kv: 1.0
```

**结论**：
- 10m/s 不是简单的速度放大
- 需要在规划时延、重规划成功率和 jerk 之间权衡
- headless 模式下才有可用结果

### Stage E：感知退化

**目的**：评估感知退化对系统的影响

**配置**：
```yaml
degradation_levels:
  - name: clean
    noise_std: 0.0
    dropout_rate: 0.0

  - name: mild
    noise_std: 0.05
    dropout_rate: 0.1

  - name: extreme
    noise_std: 0.1
    dropout_rate: 0.2
```

**结论**：
- clean 是当前最稳的基线
- mild 明显抬高控制压力
- extreme 首先损失轨迹跟踪质量

## 运行测试

### 单次测试

```bash
# Phase A 测试
roslaunch clean_uav_core benchmark_stage_a_v2_speed_1p2.launch

# Stage D 测试
roslaunch clean_uav_core benchmark_stage_d_rigid_clearance_balance.launch

# Stage E 测试
roslaunch clean_uav_core benchmark_stage_e_5p0_clean.launch
```

### 批量测试

```bash
# 运行完整测试矩阵
cd tools/benchmark_research/
python3 run_campaign.py --config campaign_config.yaml
```

### 结果分析

```bash
# 生成分析报告
python3 tools/parameter_sensitivity_analysis.py
python3 tools/pareto_frontier_analysis.py
python3 tools/risk_statistics_analysis.py
```

## 可视化

### 性能曲线

```python
import matplotlib.pyplot as plt
import json

with open("campaign_index.json") as f:
    data = json.load(f)

# 绘制速度 vs 跟踪误差
speeds = [r["config"]["max_vel"] for r in data["runs"]]
errors = [r["metrics"]["tracking_error_p95"] for r in data["runs"]]

plt.plot(speeds, errors, 'o-')
plt.xlabel("Max Velocity (m/s)")
plt.ylabel("Tracking Error P95 (m)")
plt.show()
```
