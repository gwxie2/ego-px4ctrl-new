# 系统架构详解

## 总体分层架构

本系统采用五层解耦架构，从下至上依次为：

```
╔══════════════════════════════════════════════════════════╗
║  任务/规划层                                              ║
║  EGO-Planner（路径搜索 + B样条优化 + FSM）                ║
╠══════════════════════════════════════════════════════════╣
║  控制层                                                   ║
║  px4ctrl（级联 PID + 推力模型 + 姿态控制）                ║
╠══════════════════════════════════════════════════════════╣
║  适配/胶水层                                              ║
║  clean_uav_core（里程计桥接 + 触发器 + launch 组织）      ║
╠══════════════════════════════════════════════════════════╣
║  通信中间件层                                             ║
║  MAVROS（ROS ↔ MAVLink 桥接）                            ║
╠══════════════════════════════════════════════════════════╣
║  物理/仿真层                                              ║
║  Gazebo + PX4 SITL（飞控固件模拟）                       ║
╚══════════════════════════════════════════════════════════╝
```

│                      │                                      │

## 核心组件详解

### 1. px4ctrl（位置控制器）

**有限状态机（FSM）**：

```
MANUAL_CTRL ──→ AUTO_TAKEOFF ──→ AUTO_HOVER ──→ CMD_CTRL ──→ AUTO_LAND
(RC控制)       (自动起飞)       (悬停等待)      (轨迹跟踪)    (自动降落)
```

**控制算法**：级联 PID

```
目标位置 p_des
    ↓ 位置环（Kp）
目标速度 v_des
    ↓ 速度环（Kv）
目标加速度 a_des
    ↓ 推力模型
姿态 q_des + 推力 thrust
    ↓
AttitudeTarget → MAVROS → PX4
```

**关键参数**：
- `mass`: 机体质量（1.2 kg）
- `hover_percentage`: 悬停油门（0.58）
- `Kp0/1/2`: 位置 PID 增益
- `Kv0/1/2`: 速度 PID 增益

### 2. EGO-Planner（轨迹规划器）

**规划流程**：

```
收到目标点
    ↓
A* 路径搜索
    ↓
初始化 B 样条
    ↓
梯度下降优化
    ↓
发布 /planning/bspline
    ↓
traj_server 执行求值
    ↓
发布 /position_cmd
```

**FSM 状态**：

```
INIT → WAIT_TARGET → GEN_NEW_TRAJ → EXEC_TRAJ
       ↑                           ↓
       └────────── REPLAN_TRAJ ←───┘
                   （检测障碍/偏差）
```

### 3. clean_uav_core（胶水包）

职责：
- Launch 文件组织和参数化
- 里程计适配（Gazebo → ROS）
- 起降触发器
- 规划启动触发器
- PX4 参数引导（COM_RCL_EXCEPT）

关键脚本：
- `truth_odom_adapter.py`：里程计桥接
- `takeoff_land_trigger.py`：自动起降
- `traj_start_trigger.py`：规划触发
- `px4_param_bootstrap.py`：PX4 参数设置

## 多机架构扩展

Phase 2 在 Phase 1 基础上增加命名空间隔离：

```
┌─────────────────────────────────────────────────────────────┐
│                    Phase 2 话题命名空间                      │
│                                                             │
│  /uav0/truth_odom          /uav1/truth_odom                │
│  /uav0/ego_planner_node    /uav1/ego_planner_node          │
│  /uav0/position_cmd        /uav1/position_cmd              │
│  /uav0/px4ctrl/...         /uav1/px4ctrl/...               │
│                                                             │
│  /iris_0/mavros/...        /iris_1/mavros/...              │
└─────────────────────────────────────────────────────────────┘
```

**多机关键设计**：
1. MAVROS 话题参数化（`mavros_state_topic` 等）
2. 命名空间隔离（`<group ns="uavN">`）
3. 同步触发器（`dual_traj_start_trigger.py`）
4. 轨迹广播（`/swarm/broadcast_bspline`）

## 启动时序

### 单机（Phase 1）

```
t=0s    Gazebo + PX4 SITL 启动
t=~3s   MAVROS 建立 MAVLink 连接
t=~5s   truth_odom_adapter 锁定模型
t=~5s   px4_param_bootstrap 设置参数
t=~5s   ego_planner_node 进入 WAIT_TARGET
t=10s   takeoff_land_trigger 发送起飞指令
t=~14s  无人机爬升至 1.0m
t=~15s  traj_start_trigger 触发规划
t=~15s  ego_planner 开始规划
t=~15s  px4ctrl 进入 CMD_CTRL
```

### 多机（Phase 2）

```
t=0s    启动仿真层（phase2_px4_multi_sim.launch）
t=~10s  等待 Gazebo 完全加载
t=~10s  启动算法层（phase2_dual_uav_stack.launch）
t=~15s  双机同步起飞
t=~20s  双机同步规划触发
```

## 设计原则

1. **里程计单一来源**：避免时间戳不一致
2. **规划启动门控**：确保起飞稳定后再开始规划
3. **No-RC 启动门控**：无遥控器模式下的安全保护
4. **quadrotor_msgs 本地化**：使用带定制的本地副本
5. **环境隔离**：必须 source 环境脚本
