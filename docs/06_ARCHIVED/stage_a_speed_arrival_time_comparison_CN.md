# Stage A 不同速度下的三机到达时间对比（2026-04-08）

## 1. 结论先行

从当前已经完成并可直接复核的样本看，速度从 `1.2 m/s` 提升到 `5.0 m/s` 后，三架无人机从起飞到全部到达终点的时间出现了非常明显的压缩；再提升到 `10.0 m/s` 后，整体还会继续压缩，但收益已经没有 1.2 -> 5.0 这一步那么大。

更具体地说：

- `1.2 m/s` 的三机全部到齐时间大约是 `31.846 s`。
- `5.0 m/s` 的三机全部到齐时间大约是 `10.883 s`。
- `10.0 m/s` 的三机全部到齐时间大约是 `10.768 s`。

这意味着从 `1.2 m/s` 提升到 `5.0 m/s` 时，整体验证时间大约缩短了 `20.963 s`，约 `65.9%`。
从 `1.2 m/s` 提升到 `10.0 m/s` 时，整体验证时间大约缩短了 `21.078 s`，约 `66.2%`。

## 2. 数据来源

本次对比使用的是现有 benchmark / validation 产物中的 event CSV，按每个无人机第一次出现 `EVENT_GOAL_REACHED` 的时间作为“到达终点时刻”。

## 4. 直观对比

### 4.1 第一架到达终点的时间

- `1.2 m/s`：`27.352 s`
- `5.0 m/s`：`9.036 s`
- `10.0 m/s`：`9.471 s`

从 `1.2 m/s` 提升到 `5.0 m/s`，首机到达时间缩短约 `18.316 s`。

### 4.2 最后一架到达终点的时间

- `1.2 m/s`：`31.846 s`
- `5.0 m/s`：`10.883 s`
- `10.0 m/s`：`10.768 s`

从 `1.2 m/s` 提升到 `5.0 m/s`，三机全部完成的总时间缩短约 `20.963 s`。

### 4.3 速度继续升高后的收益

从 `5.0 m/s` 到 `10.0 m/s`，三机全部到齐时间只从 `10.883 s` 进一步压到 `10.768 s`，提升非常有限。

这说明：

- 低速到中速阶段，速度提升对总完成时间的收益非常明显。
- 中速到高速阶段，收益开始变小，系统更容易被安全、重规划和控制滞后等因素限制住。

## 5. 3.0 m/s 为什么没有纳入主对比

`3.0 m/s` 的 stage A 样本最终是 `emergency_stop`，没有形成完整的 `EVENT_GOAL_REACHED` 闭环，因此不能和上面三组成功样本放在同一张“到达时间曲线”里直接比较。

这件事本身也有参考意义：

- 说明并不是速度越高就一定越好。
- 某些速度档位会暴露出更强的控制 / 安全问题，导致任务中途终止。

## 6. 结论

如果只看“从起飞到三机全部抵达终点”的时间：

- `1.2 m/s` 最慢，但最能看出系统稳定性。
- `5.0 m/s` 是当前最有性价比的提速点，完成时间压缩非常明显。
- `10.0 m/s` 还能继续缩短，但边际收益已经不如从 1.2 -> 5.0 这么大。

如果你要把这部分拿去汇报，可以直接说：

“从起飞到三机全部到齐，1.2 m/s 大约要 31.846 秒，5.0 m/s 约 10.883 秒，10.0 m/s 约 10.768 秒。也就是说，从 1.2 提到 5.0 的时间收益最明显，而继续往 10.0 提升时，收益已经趋于饱和。”
