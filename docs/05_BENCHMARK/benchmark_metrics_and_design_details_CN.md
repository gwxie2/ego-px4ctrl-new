## 1. 关键指标详解

> 注：下面文档原本聚焦飞行与规划指标。当前新增的两阶段实施方案会在此基础上补充覆盖记忆、虚拟目标检测和在线统计指标，详细落地方案见 [docs/coverage_memory_virtual_target_implementation_CN.md](coverage_memory_virtual_target_implementation_CN.md)。

### 1.1 重规划成功率（Replan Success Rate）

**定义**：在完整任务执行期间，规划器成功产出有效轨迹的重规划周期比例。

$$\text{Success Rate} = \frac{\text{有效重规划次数}}{\text{总重规划尝试次数}} \times 100\%$$

**计算方法**：
- 规划器每秒尝试 N 次重规划（通常 10–50 Hz）
- 每次重规划若 B 样条优化收敛 → 计为成功
- 若优化器超时或陷入局部最优 → 计为失败（但不停止飞行，使用上一有效轨迹）

**参考范围**：
| 范围 | 评价 | 对应场景 |
|------|------|--------|
| > 0.95 | ✅ 优秀 | 规划空间充裕，环境简单 |
| 0.90–0.95 | ✅ 良好 | 偶有重规划延迟，系统正常 |
| 0.80–0.90 | ⚠️ 可接受 | 环境复杂/速度高，规划压力大 |
| < 0.80 | ❌ 警告 | 规划失败频繁，需要参数调整 |

**为什么重要**：
- 高成功率 → 轨迹更新频繁 → 对环境变化响应迅速
- 低成功率 → 飞行器沿"老旧"轨迹运行 → 无法及时避撞 → 安全违规↑

**与其他指标的关系**：
- 成功率↑ → 跟踪误差通常↓（更新指令更频繁）
- 成功率↑ → 控制滞后可能↑（大量重规划占用 CPU）
- 成功率↑ → 抖动可能↑（频繁更换轨迹导致加速度不连续）

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| 动力学约束太紧（$v_{\max}$、$a_{\max}$ 几乎激活） | 降低速度 / 放松加速度约束 |
| 环境感知盲点导致轨迹不可达 | 扩展感知范围 / 增加 clearance |
| B 样条节点过多，优化器收敛慢 | 调整重规划频率 / 优化器参数 |
| CPU 资源竞争（GUI/Rviz 抢占） | 切换 headless 模式 |

### 1.2 最小安全间距（Min Safety Margin）

**定义**：整个任务执行期间，无人机与障碍之间的最小距离。

$$\text{Min Margin} = \min_{t \in [0, T]} \min_{i \in \text{drones}} d(pos_i(t), \text{nearest\_obstacle})$$

**计算方法**：
- 每帧采样无人机位置（100 Hz）
- 查询规划器内部网格地图中最近的膨胀后障碍体素
- 减去无人机碰撞球半径（通常 0.2–0.3 m）
- 记录最小值

**参考范围（10 m/s 阶段）**：
| 范围 | 评价 | 风险等级 |
|------|------|--------|
| > 0.3 m | ✅ 安全 | 低风险，有充分缓冲 |
| 0.25–0.3 m | ✅ 可接受 | 中低风险，仍有余量 |
| 0.15–0.25 m | ⚠️ 警告 | 中风险，接近临界 |
| < 0.15 m | ❌ 危险 | 高风险，碰撞迫在眉睫 |

**为什么重要**：
- 无人机物理尺寸 ≈ 0.3 m（rotor 到 rotor）
- 实际碰撞检测模型可能有延迟（10–50 ms）
- 高速飞行时，10 m/s 对应 0.1 m/ms，即最小间距 < 0.1 m 时已无"制动"机会

**与其他指标的关系**：
- 间距↓ → 跟踪误差↑（规划器为了躲避生成更激进的轨迹）
- 间距↓ → 重规划失败率↑（走廊宽度不足，优化器无可行解）
- 间距↑ → 任务完成时间↑（绕行距离加长）

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| swarm_clearance 太小 | 增加 `swarm_clearance` 参数 |
| 膨胀半径设置不合理 | 调大 `grid_map_obstacles_inflation` 以留余量 |
| 规划频率不足以追上高速运动 | 提升重规划频率、降低速度 |
| 感知盲区（camera FOV 不覆盖前方） | 增加感知范围、规划长期预见距离 |

### 1.3 跟踪误差（Tracking Error）— P95 百分位

**定义**：控制层实际飞行位置与规划器输出位置指令之间的欧氏距离。

$$\text{Tracking Error}(t) = \|\vec{pos}_{\text{actual}}(t) - \vec{pos}_{\text{cmd}}(t)\|_2$$

**P95 含义**：在整个任务中，跟踪误差 95% 的时间低于此值，仅 5% 的时间超过此值（峰值异常）。

$$\text{P95} = \text{quantile}(\{\text{Tracking Error}(t) \mid t \in [0, T]\}, 0.95)$$

**参考范围**：
| 速度 | 理想 P95 | 可接受 | 警告 | 危险 |
|------|---------|--------|------|------|
| 1.2 m/s | < 0.1 m | 0.1–0.3 m | 0.3–1.0 m | > 1.0 m |
| 5.0 m/s | < 0.3 m | 0.3–0.8 m | 0.8–5.0 m | > 5.0 m |
| 10.0 m/s | < 0.5 m | 0.5–1.0 m | 1.0–15.0 m | > 15.0 m |

**为什么重要**：
- 跟踪误差 = 规划意图与实际执行的偏差
- 高误差 → 规划器预测的安全轨迹在现实中可能无效 → **间接安全风险**
- 是评估 px4ctrl 级联 PID 性能的关键指标

**物理来源**：
| 来源 | 贡献量 | 备注 |
|------|--------|------|
| 控制延迟（命令→执行） | 10–50 ms | IMU、传感器延迟 |
| PID 追踪滞后 | 50–200 ms | 积分环节响应时间 |
| 规划指令超前（预测性） | 可变 | 若规划超前too much，控制器追不上 |
| 系统动态特性（惯量） | 可变 | 无人机加速/减速能力限制 |

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| px4ctrl PID 增益太低 | 提升位置环 Kp / 速度环 Kv |
| 规划指令变化太快（jerk 过大） | 增加规划器平滑权重（lambda_smooth） |
| 规划指令提前过多 | 调整规划器预见距离参数 |
| 系统实时性差（CPU 抢占） | 切换 headless，减少后台任务 |

### 1.4 控制滞后（Control Lag）— P95 百分位

**定义**：从规划器产出 `position_cmd` 到 px4ctrl 收到、处理并下达给 PX4 的时间延迟。

$$\text{Lag}(t_i) = (t_{\text{received}} - t_{\text{publish}})$$

**P95 含义**：95% 的指令处理在此延迟内完成，仅 5% 超过此值。

**参考范围**：
| 范围 | 评价 | 对应场景 |
|------|------|---------|
| < 100 ms | ✅ 优秀 | 任务关键路径无竞争 |
| 100–500 ms | ✅ 良好 | 偶有计算峰值，总体正常 |
| 500–2000 ms | ⚠️ 可接受 | 规划和控制有明显竞争，但可管理 |
| 2–5 s | ❌ 警告 | 严重的任务调度压力 |
| > 5 s | ❌ 危险 | 命令队列堆积，实时性丧失 |

**为什么重要**：
- 10 m/s 的无人机，1 秒延迟 = 10 米的位置偏离
- 高延迟 → 跟踪误差↑、间距风险↑
- 诊断系统整体 CPU 资源配置是否合理

**组成部分**（从规划器发布到 px4ctrl 确认收到）：
1. **启动延迟** (~5–10 ms)：ROS middleware 传输
2. **计算延迟** (10–50 ms/cycle)：px4ctrl 处理当前指令
3. **重规划延迟** (0–200 ms)：规划器若正在优化，新指令等待
4. **滞后传播** (100–300 ms)：多个周期的累积

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| 规划频率太低 | 提升 planner_replan_frequency |
| 优化器计算时间过长 | 降低 B 样条阶数 / 节点数 / 优化迭代 |
| CPU 竞争（GUI/Rviz） | 切换 headless 模式 |
| ROS middleware 颤抖 | 减少其他 ROS 节点 / 优先级提升 |
| px4ctrl 处理慢 | 提升 px4ctrl 运行频率 |

### 1.5 抖动积分（Jerk Integral）

**定义**：无人机加速度的变化率在整个任务中的积分。

$$\text{Jerk} = \int_0^T \left\| \frac{d\vec{a}}{dt} \right\|_2 dt = \int_0^T \left\| \frac{d^3\vec{pos}}{dt^3} \right\|_2 dt$$

**物理含义**：轨迹"抖动"的总量。低 jerk = 轨迹光滑连贯，高 jerk = 轨迹有频繁的加速度变化（机械系统负荷大）。

**参考范围**（基于 15 秒任务的积分值）：
| 范围 | 评价 | 对应特性 |
|------|------|---------|
| < 20 | ✅ 优秀 | 轨迹非常光滑，低应力 |
| 20–50 | ✅ 良好 | 轨迹光滑，低频重规划 |
| 50–100 | ⚠️ 可接受 | 轨迹中等波动，可管理 |
| 100–150 | ⚠️ 警告 | 轨迹有明显抖动 |
| > 150 | ❌ 严重 | 频繁加速度变化，机械损伤风险 |

**为什么重要**：
- **机械寿命**：高 jerk 导致电机/浆叶频繁受力变化 → 加速疲劳损伤
- **能耗**：频繁加速度变化 → 电烧更多 → 续航↓
- **感应器噪声**：高频抖动 → IMU 噪声大 → 状态估计精度↓
- **乘坐舒适性**：若无人机携带设备/货物 → 高 jerk 导致装载物滑动/受损

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| 重规划频繁（轨迹频繁更换） | 降低重规划频率 / 增加平滑权重 |
| 平滑权重太低（lambda_smooth） | 增加 `planner_lambda_smooth` 参数 |
| PID 增益过高（控制震荡） | 降低 px4ctrl 的 Kv（速度环增益） |
| 障碍突现导致急转向 | 增加感知范围 / 提前规划 |

### 1.6 安全违规计数（Safety Violation Count）

**定义**：在整个任务中，无人机与障碍间距短暂低于膨胀阈值的事件计数。

$$\text{Violations} = \#\{t \mid d(pos, \text{obstacle}) < \text{inflation\_radius}\}$$

**计算方法**：
- 每帧检查间距（100 Hz）
- 一旦 $d < \text{inflation}$，计数 +1
- 多帧连续违规依然计为 1 次违规事件（使用 hysteresis，避免计数抖动）

**参考范围**（15 秒任务，100 Hz 采样）：
| 范围 | 评价 | 风险说明 |
|------|------|--------|
| 0–10 | ✅ 优秀 | 极少碰到膨胀边界 |
| 10–50 | ✅ 良好 | 偶尔接触，在可控范围 |
| 50–200 | ⚠️ 可接受 | 频繁接触，但未真实碰撞 |
| 200–500 | ❌ 警告 | 严重超限，安全风险大 |
| > 500 | ❌ 极端 | 几乎全程接触障碍，系统失效 |

**为什么重要**：
- 膨胀间距虽然 > 0，但不代表完全安全（延迟、感知误差、模型偏差）
- 频繁接触膨胀边界 → 系统余量耗尽 → 任何小扰动都可能真实碰撞
- 是**可靠性**和**稳健性**的关键指标

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| swarm_clearance 太小 | 增加 `swarm_clearance` 参数 |
| inflation_radius 设置不合理 | 适度增大膨胀半径 |
| 重规划失败率高 | 改善规划成功率（见 1.1） |
| 感知延迟大 | 提升感知频率、扩展预见范围 |

### 1.7 规划优化器失败计数（Optimizer Failure Count）

**定义**：在所有重规划周期中，B 样条优化器无法在规定时间内收敛的的次数。

**原因分类**：
| 原因 | 代码标志 | 说明 |
|------|---------|------|
| 超时（time limit reached） | `OPT_TIMEOUT` | 优化器运行超过预设时间上限 |
| 无可行解（infeasible） | `OPT_INFEASIBLE` | 动力学或轨迹约束无法满足 |
| 数值不稳定 | `OPT_NUMERICAL` | 线性系统求解失败 |
| 最大迭代（reached max iterations） | `OPT_MAX_ITER` | 优化还未收敛就达到上限 |

**参考范围**（相对于总重规划次数）：
| 失败率 | 评价 | 说明 |
|--------|------|------|
| < 1% | ✅ 优秀 | 优化器工作正常，极少失败 |
| 1–5% | ✅ 良好 | 偶有边界情况 |
| 5–10% | ⚠️ 可接受 | 环境复杂，存在规划难点 |
| 10–30% | ❌ 警告 | 系统可用但稳定性有问题 |
| > 30% | ❌ 严重 | 规划器根本无法满足约束 |

**为什么重要**：
- 优化失败 → 沿上一可行轨迹继续飞行 → 无法对新情况响应 → **间接安全风险**
- 是诊断参数设置是否过于激进的指标

## 2. 覆盖记忆与虚拟目标指标（新增规划中）

### 2.1 全局覆盖率（Cumulative Coverage）

**目标**：衡量在 80m x 80m 地图上，低分辨率覆盖网格中已被 FoV 扫描到的有效面积占比。

**建议定义**：

$$
	ext{Coverage}(t) = \frac{A_{\text{explored}}(t)}{A_{\text{valid}}} \times 100\%
$$

### 2.2 探索率（Exploration Rate）

**目标**：衡量单位时间新增覆盖面积，便于比较不同速度下的搜索敏捷性。

$$
	ext{Exploration Rate}(t) = \frac{\Delta A_{\text{explored}}}{\Delta t}
$$

### 2.3 冗余因子（Redundancy Factor）

**目标**：衡量被两架或以上无人机重复扫过的面积比例，越低越好。

**建议定义**：

$$
	ext{Redundancy} = \frac{A_{\ge 2\ \text{hits}}}{A_{\text{explored}}}
$$

### 2.4 虚拟目标首次发现时间（Time to First Detection）

**目标**：当任意无人机进入目标距离阈值并且目标位于当前 FoV 投影内时，记录首次发现时刻。

**实现约束**：

- 必须使用 ROS 时间戳。
- 必须支持 `target_positions` 从参数服务器读取。
- 必须支持 1.2 m/s 基线验证，不改变现有 planner / px4ctrl C++。

### 2.5 轨迹平滑度（Jerk）

当前 benchmark_manager 已经通过 odom 和 position_cmd 计算 jerk 积分；新增 helper 只需要复用这一逻辑并把它纳入覆盖 / 目标任务的统一报表。

### 2.6 新增状态机输出

未来覆盖模块建议输出两个运行时事件：

- 覆盖度 / 探索率 / 冗余因子摘要
- TargetDetected 事件及其时间戳

这两个输出都应保持与现有 summary / campaign index 链路兼容。
| 原因 | 改善方法 |
|------|---------|
| 动力学约束太紧 | 降低 `vmax` / `amax` |
| 环境太复杂，无可行走廊 | 扩展感知 / 增大 clearance |
| B 样条自由度太多 | 减少样条节点数 / 控制点 |
| 优化器超时太短 | 增加 `optimizer_time_limit` 参数 |
| 初值不好（上一条轨迹跨度太大） | 调整规划频率 / 初值生成策略 |

### 1.8 碰撞触发计数（Collision Trigger Count）

**定义**：紧停系统（Emergency Stop Logic）被触发的次数。当检测到极度危险（$d < 0.1$ m 或将要碰撞）时，自动切入 HOVER 状态。

| 触发条件 | 风险等级 | 后果 |
|---------|--------|------|
| $d < 0.05$ m | 🔴 极端 | 立即触发紧停 |
| 预测碰撞 | 🔴 极端 | 前向预测显示1秒内会碰 |
| TrajServer 无效指令 | 🟡 严重 | 回退保守行为 |

**参考范围**：
| 次数 | 评价 | 说明 |
|-----|------|------|
| 0 | ✅ 完美 | 从未需要紧停 |
| 1–2 | ⚠️ 可接受 | 偶有险情但系统妥善处置 |
| > 3 | ❌ 不可接受 | 系统可靠性有问题 |
| > 5 | ❌ 失败 | 配置不适合此场景 |

**改善方式**：
| 原因 | 改善方法 |
|------|---------|
| 参数各个指标都差（综合问题） | 整体调优参数 |
| 最小间距边界判定有误 | 检查膨胀参数设置 |
| 规划器无法应对 | 降速 / 增加感知范围 |

---

### 1.9 终止原因（Stop Reason）

**定义**：任务执行何时结束的原因分类。

| 终止原因 | 代码 | 说明 | 评价 |
|---------|-----|------|------|
| 所有目标抵达 | `all_goals_reached` | 3 架无人机都飞到各自目标点 | ✅ 成功 |
| 紧停（安全） | `emergency_stop` | 系统主动切入紧停以避免碰撞 | ⚠️ 部分成功 |
| 超时（基准管理器） | `benchmark_timeout` | 飞行时间超过预设上限（通常 60 s） | ❌ 失败（配置问题） |
| 规划器死锁 | `planner_timeout` | 规划器无法恢复 | ❌ 失败 |
| 控制器无响应 | `controller_timeout` | 收不到规划指令 | ❌ 失败 |
| 通信丢失 | `comm_lost` | MAVROS 与 PX4 断开 | ❌ 失败（系统级） |
| 未知原因 | `unknown` | 基准管理器检测异常但原因待查 | ❌ 失败 |

**理想情况**：
```
┌─────────────────────────────────────────────┐
│         stop_reason = "all_goals_reached"   │
│         + collision_trigger_count = 0       │
│         + emergency_stop_count = 0          │
└─────────────────────────────────────────────┘
        → 任务完美完成
```

## 2. 各 Stage 的方案设计详解

### 2.1 Stage A — 速度梯度压力测试

#### 方案：`v2_speed_1p2` / `v2_speed_3p0` / `v2_speed_5p0`

**设计意图**：
1. **验证规划器可伸缩性**：能否随速度线性下降而正确宽松动力学约束
2. **找出性能悬崖**：在哪个速度点开始出现明显性能下行
3. **为后续阶段建立基准线**：低速下的理想性能作为对标

**参数对比**：
